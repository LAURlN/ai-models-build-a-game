**A.** Broad, compact CommonJS API, transactional synchronous hooks, seeded state, native helpers, memory retrieval, procedural presentations/audio, and a credible two-encounter fake E2E. Its zero-live-run log is candid. Defects: **blocking for Codex**, the Narrator schema uses an open `worldPatch` object (`additionalProperties:true`), incompatible with the strict output-schema path ([campaignDirector.ts:15](A/game/src/main/campaignDirector.ts:15)); B's live diagnostic identifies this exact provider constraint. Returning to Battle after publishing aftermath still permits rewind/load ([index.ts:167](A/game/src/main/index.ts:167)), while outcome deduplication preserves the old campaign result ([campaignDirector.ts:157](A/game/src/main/campaignDirector.ts:157)): replayed casualties/captures diverge from canon. Campaign actions discard unit edits, copying back only extension state ([campaignDirector.ts:169](A/game/src/main/campaignDirector.ts:169)). Story presentation faults are discarded without repair ([campaignDirector.ts:45](A/game/src/main/campaignDirector.ts:45)). Tests cover 48-unit AI, module timeouts and rewind; the campaign E2E actually attacks/captures but ends both battles by conceding.

**B.** Substantial typed API and the strongest provider-schema diagnostic after D: five logged cheap calls cover a real helper writing TypeScript and loading a capture system. E2E plays a capture battle, starts another and resumes it, although its scenario has only 16 units. Defects: hook callbacks execute outside the VM timeout, mutate live state without rollback, and accept async returns ([extensionRuntime.ts:471](B/game/src/rules/extensionRuntime.ts:471)); a looping campaign panel also runs in Electron's main process ([campaignCoordinator.ts:486](B/game/src/main/campaignCoordinator.ts:486)). Maps silently cap at 80×80 ([campaign.ts:993](B/game/src/rules/campaign.ts:993)); the stock triangle remains hard-coded ([battle.ts:271](B/game/src/rules/battle.ts:271)). New encounters recreate every proposed unit alive with fresh HP/statuses, ignoring the supplied persistent roster ([campaign.ts:1033](B/game/src/rules/campaign.ts:1033)). Helper completion reruns every module's battle initialization, potentially resetting an active encounter ([battleHost.ts:81](B/game/src/main/battleHost.ts:81)). Required modules can launch after failure because only running statuses block entry ([campaignCoordinator.ts:932](B/game/src/main/campaignCoordinator.ts:932)). Structured UI widgets also constrain arbitrary screens. Extension/scale/SQLite tests are useful, but do not establish hanging-hook recovery.

**C.** Best incremental extension foundation: explicit movement/combat/AI/outcome hooks, unrestricted scripted panels, drawing error attribution, native helpers, source snapshots, and a persisted command-result cache that even stabilizes native random results after rewind. Tests exercise 100 units, generated combat forecasts, synchronous hangs, two battles, repair and audio mixing; E2E includes panel-error repair and restart, but concedes both encounters. Zero live calls are disclosed. Defects: rejected async hooks are detected without consuming their rejected Promise ([extensionRuntime.ts:64](C/game/src/main/extensionRuntime.ts:64)); an `async action(){throw Error(...)}` therefore escapes isolation as an unhandled rejection and can terminate the battle worker. Deferred Promise callbacks also run outside the synchronous watchdog. Campaign UI actions operate on the stock battle roster, and copy back neither roster edits nor ordinary campaign inventory ([campaignService.ts:115](C/game/src/main/campaignService.ts:115), [campaignService.ts:117](C/game/src/main/campaignService.ts:117)). Narrator roster patches similarly never update the canonical roster ([campaignService.ts:77](C/game/src/main/campaignService.ts:77)). Thus companion recruitment/equipment management needs additional integration despite the broad API.

**D.** Most complete realization: free-form stats/weapons/factions, declarative and executable mechanics, generated map/AI/objective registries, genuine non-grid modes, live DOM/Pixi extensions, campaign commands, archival memory, adaptive sound, and worker watchdog recovery. Tests cover large multi-faction battles, two-battle continuity, rewind and actual worker termination; E2E checks concurrent chat/building, capture and a playable non-grid duel. Ten logged cheap calls describe both useful findings and interrupted helpers, rather than claiming a completed live full loop. Defects: generated imports/setup execute directly in the renderer ([moduleRuntime.ts:46](D/game/src/renderer/world/moduleRuntime.ts:46)); panel rendering is likewise uninterruptible, and thrown view errors only update local error text, never dispatch repair ([ui.tsx:64](D/game/src/renderer/world/ui.tsx:64)). Selection/forecast faults quarantine modules silently without the host emitting a repair event ([battle.ts:1224](D/game/src/engine/battle.ts:1224), [battle.ts:1253](D/game/src/engine/battle.ts:1253)). Rewind restores state but retains the current external registry ([worldHost.ts:362](D/game/src/main/world/worldHost.ts:362)); edited module code is not pinned to saved boundaries. Interrupted helper tasks are only in-memory and disappear on restart ([director.ts:43](D/game/src/main/world/director.ts:43)).

**E.** Useful conservative additions: persistent roster continuity, faction relationships, straightforward extension actions, synthesized cues and a real fake-provider two-battle/restart test. The README honestly acknowledges its narrow API. Defects: source and hooks execute via unguarded `Function`/direct calls ([extensionRuntime.ts:23](E/game/src/main/extensionRuntime.ts:23), [extensionRuntime.ts:65](E/game/src/main/extensionRuntime.ts:65)); a hanging hook permanently kills the worker after timeout without module repair/recovery ([gameHost.ts:47](E/game/src/main/gameHost.ts:47)). Chapter schemas add optional properties outside `required`, breaking Codex strict generation ([campaign.ts:180](E/game/src/rules/campaign.ts:180), [campaign.ts:188](E/game/src/rules/campaign.ts:188)); local fallback can conceal this. Editing an existing system outside repair resets its durable data/RNG ([storyCoordinator.ts:125](E/game/src/main/storyCoordinator.ts:125)). Only command/action hooks and generic data/buttons exist: no generated screens, visual API or non-grid encounters. Tests cover ordinary failures and seeded rewind, but not hanging hooks; the E2E's helper is manually requested and its battles are conceded. No live generation is claimed.

## Recommendation

Ranking: **D > C > A > B > E**. Adopt D for its materially broader game model and working non-grid path, after repairing renderer isolation and fault forwarding. Port C's transactional fresh-context execution, source snapshots and replay cache; A's repair-aware history refresh; B's strict-schema normalization and live diagnostic practice; E's explicit roster/equipment/status continuity. Add live-provider schema tests and failure cases spanning presentation, rewind and campaign canon before accepting the combined base.
